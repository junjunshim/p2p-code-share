# P2P Code Share Extension

이 프로젝트는 별도의 서버 없이 WebRTC를 사용하여 VS Code 인스턴스 간에 실시간으로 코드를 공유하고 편집할 수 있는 P2P 기반 협업 도구입니다.

## 🚀 주요 기능
*   **간편한 자동 연결 (PeerJS)**: 방 이름만으로 복잡한 SDP 복사 없이 즉시 P2P 연결이 가능합니다. (PeerJS 무료 시그널링 서버 활용)
*   **서버리스 P2P 직접 통신**: 실제 데이터 교환은 WebRTC(SimplePeer)를 사용하여 중앙 서버를 거치지 않고 직접 통신합니다.
*   **실시간 코드 및 커서 동기화**: 문서 변경 사항 및 다수 참가자의 커서 위치/선택 영역을 실시간으로 시각화합니다.
*   **파일 공유 및 자동 동기화**: 호스트가 공유한 파일을 게스트가 즉시 열람할 수 있으며, 중간에 입장한 게스트도 현재 공유 중인 모든 파일을 자동으로 전달받습니다.
*   **사용자 관리**: 각 참가자별 고유 색상 할당, 이름 변경 기능을 제공합니다.

## 📂 디렉터리 구조
```text
src/
├── core/                        # P2P 동기화 엔진 및 핵심 비즈니스 로직
│   ├── HubManager.ts            # Webview(엔진)와의 메시지 통신 인터페이스 및 시그널링 조율
│   ├── SyncEngine.ts            # 동기화 오케스트레이터 (각 서브 매니저 조율 및 상태 관리)
│   └── sync/                    # 기능별 세부 매니저 모듈
│       ├── DocumentSyncManager.ts   # Yjs(CRDT) 기반 실시간 문서 변경 및 충돌 없는 병합 관리
│       ├── ParticipantManager.ts    # 참여자 목록, 승인/거절, 권한 부여 및 핑퐁 상태 감지
│       ├── SessionRecoveryManager.ts # 창 전환/재시작 시 세션 영구 저장 및 자동 복원
│       ├── FileStorageManager.ts    # 공유 파일 관리, 로컬 임시 저장소 및 읽기 전용 상태 제어
│       ├── CursorManager.ts         # 참가자별 실시간 커서/선택영역 시각화 및 필터링
│       └── DecorationManager.ts     # 코드 라인 메모/북마크(데코레이션) 관리 및 이동
├── ui/                          # VS Code UI 컴포넌트 및 웹뷰 템플릿
│   ├── SidebarProvider.ts       # 컨트롤 패널 사이드바 웹뷰 프로바이더
│   ├── ChatPanel.ts             # P2P 실시간 인앱 채팅 웹뷰 패널
│   └── templates/               # 웹뷰 HTML/CSS/JS 템플릿 모듈
│       ├── engine/              # Webview 백그라운드 P2P 통신 엔진 (PeerJS/SimplePeer)
│       └── sidebar/             # 사이드바 컨트롤 패널 뷰 (body, script, styles)
├── types/                       # P2P 메시지, 세션, 데코레이션, 권한 인터페이스 정의
├── utils/                       # 경로 정규화, OS 호환성 EOL 처리 등 헬퍼 함수
└── extension.ts                 # 익스텐션 진입점(Activation) 및 명령어 등록
```

## 🛠 핵심 기술: 실시간 동기화 아키텍처

### 1. 하이브리드 시그널링 & WebRTC 데이터 통로 (PeerJS + SimplePeer)
*   **간편 자동 시그널링**: `PeerJS`를 활용하여 방 이름을 해시 코드로 인코딩하고 브로커 서버에 등록합니다. 이를 통해 복잡한 수동 교환 없이 사용자 간 초기 WebRTC 핸드셰이크(SDP 교환)를 자동화합니다.
*   **수동 SDP 교환 모드**: 외부 시그널링 서버 접근이 제한된 폐쇄망 환경을 위해 직접 SDP 텍스트를 복사/붙여넣기하여 연결하는 수동 모드도 함께 지원합니다.
*   **순수 P2P 데이터 전송**: WebRTC 채널이 수립된 후에는 모든 소스 코드 변경 사항, 커서 위치, 채팅 데이터가 중앙 서버를 거치지 않고 `SimplePeer` 직접 통신 채널을 통해 암호화되어 전송됩니다.
*   **대칭형 NAT/방화벽 대응 (TURN Support)**: 사용자 설정(`settings.json`)에 TURN 서버 정보를 지정할 수 있어, 사설망이나 엄격한 방화벽 환경에서도 릴레이를 통해 안정적인 P2P 연결을 보장합니다.

### 2. Yjs (CRDT) 기반 실시간 충돌 없는 동시 편집 (`DocumentSyncManager`)
*   **CRDT 알고리즘 적용**: 단순 텍스트 덮어쓰기나 락(Lock) 방식 대신, 산업 표준 충돌 없는 분산 데이터 모델인 **Yjs(CRDT)**를 탑재했습니다.
*   **무손실 실시간 병합**: 여러 사용자가 동일한 파일의 같은 라인을 동시에 타이핑해도 데이터 유실이나 덮어쓰기 충돌 없이 글자 단위로 정확하게 병합됩니다.
*   **스냅샷 + 델타 업데이트**: 신규 게스트 입장 시 현재 Yjs 문서의 전체 상태 벡터를 인코딩하여 즉시 동기화하며, 이후 편집 발생 시에는 변경된 바이트 단위의 델타(`YJS_UPDATE`)만 경량 전송하여 네트워크 대역폭을 최적화합니다.
*   **에디터-Yjs 동기화 가드**: `onDidChangeTextDocument` 이벤트와 Yjs `observe` 리스너 간의 무한 동기화 루프를 방지하는 상호 배제 플래그 시스템을 운영합니다.

### 3. 세션 영구 보존 및 무중단 재연결 (`SessionRecoveryManager`)
*   **작업 공간 전환 대응**: 호스트가 VS Code에서 작업 폴더를 변경하거나 새 창을 열 때(`Reload Window`, `Open Folder`), `globalState`에 세션 정보(방 이름, 공유 파일 목록, Yjs 문서 상태, 참가자 명단, 채팅 기록)를 영구 스냅샷으로 저장합니다.
*   **하트비트 생존 보고**: 활성 호스트 창이 2초마다 하트비트를 기록하여, 창 닫힘 및 비정상 종료를 감지하고 유효한 세션만 자동 복원합니다.
*   **게스트 30초 유예 기간(Grace Period)**: 호스트 창이 전환되는 동안 게스트의 에디터를 일시 잠금(`readonly`) 처리하여 오프라인 충돌을 방지하고, 30초 동안 호스트에게 주기적으로 자동 재접속을 시도하여 무중단 복귀를 제공합니다.

### 4. 실시간 연결 모니터링 & 상태 동기화 (`ParticipantManager`)
*   **Ping-Pong 헬스체크**: 호스트가 4초마다 모든 게스트에게 `PING`을 전송하고 `PONG` 응답 시간을 검사하여, 실시간 연결 상태(`connected` / `reconnecting`)를 호스트 UI에 직관적으로 시각화합니다.
*   **타임아웃 자동 정리**: 호스트 복원 후 게스트가 재연결 대기 상태에서 퇴장하거나 연결 불가 상태가 되면, 30초 유예 기간 후 참가자 명단에서 자동으로 제거합니다.
*   **참여자 격리 및 권한 제어**: 호스트의 승인을 득한 정식 피어에게만 파일 스냅샷과 변경 이벤트를 중계하며, 사용자별 읽기/쓰기 권한 및 파일별 단독 담당자(Owner) 권한을 런타임에 동적으로 제어합니다.

### 5. 실시간 시각화 및 협업 기능 (`CursorManager` & `DecorationManager`)
*   **커서 & 선택 영역 트래킹**: 참여자별 고유 색상과 닉네임 태그를 매핑하여 원격 커서 및 다중 라인 선택 영역을 에디터 내에 실시간 렌더링합니다.
*   **호스트 팔로우 모드**: 호스트가 파일을 이동하거나 스크롤할 때 게스트의 활성 에디터를 동일한 위치로 자동 이동시켜 원격 코드 리뷰를 지원합니다.
*   **인라인 데코레이션(메모)**: 코드 특정 위치에 텍스트 메모나 가이드를 남겨두고 클릭 한 번으로 해당 라인으로 점프할 수 있는 협업 도구를 제공합니다.


## ⚠️ 네트워크 연결 문제 해결 (Troubleshooting)

이 프로젝트는 WebRTC 기반의 P2P(Peer-to-Peer) 직접 통신 방식을 사용하므로, 사용자의 네트워크 토폴로지(공유기, 방화벽, 사설 IP 환경)에 따라 연결 성공 여부가 결정됩니다.

### 1. 연결 유형 및 권장 환경
*   **직접 P2P 연결 (Direct P2P)**
    *   **동일 공유기/서브넷 (LAN / Wi-Fi)**: NAT 변환이 필요 없어 지연 시간이 가장 짧고 안정적입니다.
    *   **Full Cone NAT / 포트 포워딩 환경**: 공인 IP가 할당되어 있거나 관대한 NAT 환경에서는 외부 네트워크 간에도 직접 P2P 연결이 가능합니다.
*   **TURN 중계 연결 (Relayed via TURN)**
    *   **서로 다른 외부 네트워크, LTE/테더링, 기업/학교 망**: 대칭형 NAT(Symmetric NAT) 또는 기기간 직접 패킷 전달을 차단하는 엄격한 방화벽 환경에서는 **TURN 서버**를 통해 중계 연결되어 100% 연결을 보장합니다.

---

### 2. 연결이 되지 않을 때 체크리스트

#### ① 서로 다른 네트워크/인터넷 환경에서 연결 실패 시 (TURN 설정)
*   **원인**: 양측 사용자가 서로 다른 공유기(NAT)에 있거나 대칭형 NAT 환경에 있으면 WebRTC P2P 홀펀칭(STUN)이 불가능합니다.
*   **해결 방법**: **TURN 서버를 설정**하면 방화벽을 우회하여 중계 연결됩니다.
    1. VS Code 설정(`Ctrl + ,` 또는 `Cmd + ,`)을 열고 `p2pCodeShare`를 검색합니다.
    2. `settings.json`에 TURN 서버 정보를 입력합니다:
       ```json
       {
         "p2pCodeShare.turnUrl": "turn:your-turn-server.com:3478",
         "p2pCodeShare.turnUsername": "your_username",
         "p2pCodeShare.turnCredential": "your_password"
       }
       ```
    > [!TIP]
    > 연결이 TURN을 통해 수립되면 상단 상태 배지에 `CONNECTED (TURN)`으로 표시됩니다. 무료 오픈 TURN 서비스(예: Metered, OpenRelay 등) 또는 자체 `coturn` 서버를 활용할 수 있습니다.

#### ② 동일 Wi-Fi 환경인데 연결이 안 되는 경우 (AP Isolation)
*   **원인**: 카페, 기숙사, 기업 Wi-Fi 또는 일부 가정용 공유기의 **'AP Isolation(Client Isolation)'** 기능이 켜져 있으면, 동일한 Wi-Fi에 접속해 있어도 내부 기기 간의 통신이 강제로 차단됩니다.
*   **해결 방법**:
    *   공유기 관리자 페이지에서 `AP Isolation` 또는 `내부 네트워크 기기 간 통신 허용` 옵션을 확인합니다.
    *   Windows의 경우 네트워크 프로필을 **'공용 네트워크'**에서 **'개인 네트워크'**로 변경하고, 방화벽에서 VS Code 인바운드 통신을 허용합니다.

#### ③ PeerJS 시그널링 서버 접근 불가 (방 생성/참여 무한 로딩)
*   **원인**: 네트워크 정책상 무료 공용 시그널링 서버(`0.peerjs.com`) 도메인 또는 포트 접근이 차단된 경우입니다.
*   **해결 방법**:
    *   자동 연결 대신 **수동 SDP 교환 방식**을 사용합니다.
    *   호스트는 `Invite Guest`로 생성된 SDP 텍스트를 게스트에게 전달하고, 게스트는 `Join (Manual)`으로 SDP를 붙여넣어 외부 시그널링 서버 없이도 연결할 수 있습니다.

#### ④ 방 이름 중복 오류 (`Room Name Already in Use`)
*   **원인**: PeerJS 공용 브로커 서버에 이미 다른 사용자가 동일한 방 이름으로 등록되어 있는 경우입니다.
*   **해결 방법**: 호스트는 유니크한 고유 방 이름(예: `myproject-room-2026`, 영문/숫자 조합)을 입력해 주세요.

## ⚙️ 사용 및 개발 설정 방법 (Setup & Usage)

### 1. 일반 사용자 가이드 (User Usage)

#### 호스트 (Host)
1. VS Code 좌측 액티비티 바에서 **P2P Code Share** 아이콘을 클릭합니다.
2. **Create Sharing Room**을 누르고 고유한 **방 이름(Room Name)**을 입력한 뒤 **START ENGINE**을 클릭합니다.
3. 공유할 소스 코드 파일을 에디터에서 열고, 사이드바의 **Share File** 버튼이나 탐색기 우클릭 메뉴를 통해 공유 목록에 등록합니다.
4. 게스트가 입장을 요청하면 사이드바 상단 알림에서 **Approve(승인)** 버튼을 눌러 수락합니다.
5. 필요 시 게스트별 쓰기 권한 토글, 파일 담당자 지정, 호스트 팔로우 모드(Follow Me)를 자유롭게 제어할 수 있습니다.

#### 게스트 (Guest)
1. **P2P Code Share** 사이드바를 열고 **Join Sharing Room**을 클릭합니다.
2. 호스트가 전달해 준 **방 이름(Room Name)**과 사용할 본인의 **닉네임(Name)**을 입력한 후 **JOIN (AUTO)**를 누릅니다.
3. 호스트가 승인을 완료하면, 호스트가 공유한 파일들이 자동으로 로컬 임시 작업 공간에 복제되어 열리며 실시간 동시 편집에 참여할 수 있습니다.

---

### 2. 로컬 개발 및 기여 가이드 (Developer Setup)

1. **저장소 클론 및 의존성 설치**:
   ```bash
   git clone https://github.com/junjunshim/p2p-code-share.git
   cd p2p-code-share
   npm install
   ```

2. **빌드 및 감시 모드 실행**:
   ```bash
   # 코드 변경 시 실시간 증분 컴파일
   npm run watch

   # 프로덕션 번들 컴파일
   npm run compile
   ```

3. **VS Code Extension Host 디버깅**:
   - VS Code에서 프로젝트를 열고 `F5` 키를 누르면 새 창으로 **Extension Development Host**가 실행됩니다.
   - 호스트 창과 게스트 창 2개를 띄워 로컬에서 실시간 P2P 세션을 바로 테스트할 수 있습니다.

4. **익스텐션 패키징 (.vsix 생성)**:
   ```bash
   npx @vscode/vsce package
   ```
